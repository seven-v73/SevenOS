# SevenOS Prism Flow Charter

> One identity. Several facets. One coherent system.

SevenOS Prism Flow is the official identity direction for SevenOS. It moves the
system away from borrowed desktop references and toward a native SevenOS visual
and interaction language.

SevenOS is not a macOS-like Linux desktop. SevenOS is a context-aware operating
system built around one user identity, one system core and several Mini OS
facets.

## Identity Thesis

SevenOS should be recognized by:

- the Seven Prism symbol
- contextual Mini OS facets
- calm system intelligence
- precise state language
- sober depth instead of decorative glass
- fluid transitions between work contexts
- Linux-native freedom with a product-grade surface

The visual metaphor is the prism: one source, several focused directions.

```text
User identity
  -> Seven Core
  -> Prism context
  -> Mini OS facet
  -> focused workflow
```

## Core Personality

SevenOS should feel:

- clear
- grounded
- fluid
- sovereign
- intelligent
- precise
- alive without noise
- futuristic without imitation

SevenOS should not feel:

- like a macOS clone
- like generic cyberpunk
- like a theme pack
- like a dashboard website
- like a pile of terminal wrappers
- like glass for the sake of glass

## Visual DNA

### Prism

The Prism is the core mark and the core behavior.

- It represents one system splitting into focused Mini OS facets.
- It guides profile transitions.
- It defines angular highlights, light lanes and state signals.
- It replaces borrowed dock/window metaphors as the main SevenOS identity.

### Facets

Facets are contextual zones of the OS:

- Equinox: balance and daily system control
- Forge: development and deployment
- Shield: trust and cybersecurity
- Studio: creation
- Pulse: gaming and performance
- Baobab: culture, memory and transmission
- Atlas: exploration, maps, documents and knowledge

Facets should color and tune the OS subtly. They should not become unrelated
themes.

### Flow

Flow is the movement between states:

- intent appears
- context is detected
- plan is previewed
- action is confirmed when needed
- progress is visible
- result is verified
- next action is offered

Motion should explain this flow, not decorate it.

## Shape Language

SevenOS should use:

- compact prism marks
- angular light lanes
- fine separators
- clear rectangular layouts
- controlled radius
- status rails
- side/context rails
- instrument-like panels

Radius direction:

| Element | Radius |
| --- | --- |
| Tiny controls | 6px |
| Buttons and inputs | 8px |
| Panels and cards | 10px |
| Dialogs and sheets | 14px |
| Prism passage overlays | 18px |
| Pills only when semantically needed | 999px |

Large macOS-like rounded panels should not be the default system shape.

## Material Language

SevenOS keeps depth, but changes the rule:

```text
Depth first. Glass second.
```

Use:

- mineral dark surfaces
- translucent overlays only where context changes or focus requires them
- thin borders
- light lanes
- restrained gradients
- profile accent edge signals

Avoid:

- oversized glass sheets
- decorative blur everywhere
- floating panels without purpose
- one-note blue/violet/cyan neon
- glossy imitation of another OS

## Typography

SevenOS should use free, Linux-native typography by default:

- Interface: Inter or Noto Sans
- Body: Noto Sans
- Mono: JetBrains Mono
- Cultural/language coverage: Noto family

SF Pro can remain a compatibility fallback if installed, but it is not the
SevenOS identity.

Typography rules:

- no heavy decorative headings in system panels
- clear hierarchy over large hero text
- compact labels for dense OS surfaces
- readable body copy in French and English
- mono only for code, logs, telemetry and cyber details

## Shell Direction

SevenOS should move from borrowed desktop metaphors toward its own shell model.

### Context Rail

The Context Rail is the SevenOS replacement direction for a generic dock clone.

It should expose:

- active Mini OS
- pinned apps
- current workflow
- running jobs
- profile actions
- trust state

It may be horizontal or vertical depending on layout, but it must feel like a
SevenOS context instrument, not a macOS Dock copy.

### Prism Bar

The top/system bar should behave like a Prism Bar:

- identity and Mini OS context
- Spotlight/intent entry
- active jobs and state
- trust/network/audio/power
- no decorative modules

### Prism Passage

Mini OS switching should use Prism Passage:

- current facet fades back
- target facet lights up
- required services prepare
- SevenOS reports readiness

The passage is not just an animation; it is a visible runtime state.

## Component Language

SevenOS components should be reusable and stateful:

- Action Row
- Status Rail
- Job Progress
- Confirmation Sheet
- Prism Switcher
- Context Card
- Details Drawer
- Trust Badge
- Mini OS Facet Button
- Recovery Banner

Every component must support:

- ready
- running
- warning
- blocked
- failed
- completed
- loading/stale

## Copy And Tone

SevenOS copy should be calm, direct and sovereign.

Use:

- "Prepare"
- "Verify"
- "Apply"
- "Recover"
- "Open details"
- "Switch context"
- "Trust state"
- "System facet"

Avoid:

- "magic"
- "awesome"
- "macOS-style"
- "cyberpunk"
- "hack mode"
- terminal-first wording for public workflows

## Cultural Identity

SevenOS can carry African-rooted identity, but structurally.

Use culture through:

- Baobab as memory and transmission
- vocabulary of roots, knowledge, community and continuity
- subtle geometry
- offline knowledge and language support
- Signal Gold, Baobab Green and Atlas Teal as calm accents

Avoid culture as surface decoration or motif overload.

## Non-Negotiables

- Atlas is the exploration and knowledge Mini OS. Do not call it Nexus.
- The Prism is the public SevenOS symbol.
- Scripts are not the public product language.
- Glass is a material, not the identity.
- Mini OS facets must feel connected to one Seven Core.
- Public workflows must expose state, progress and recovery.
- SevenOS should be Linux-native and visually independent.

## First Implementation Targets

1. Replace borrowed style references in docs and identity contracts.
2. Move token names toward Prism Mineral while keeping compatibility aliases.
3. Redesign shell language around Context Rail, Prism Bar and Prism Passage.
4. Make status and job components the basis of Hub, Settings and Shell.
5. Use profile accents as facets, not full separate themes.
6. Treat layout, accessibility and performance as part of the identity.
